ChatGPT connects to your server as a *custom MCP app*, created from the
**Plugins** page. Because ChatGPT runs in OpenAI's cloud (not
locally), you point it at your public **streamable-HTTP** endpoint at `/mcp`,
never `localhost`.

<Callout type="info" title="Account requirements">
Custom MCP apps need ChatGPT **Plus, Pro, Business, Enterprise, or Edu**, on
the web. On Business/Enterprise/Edu a workspace admin must allow them first.
ChatGPT **Free** cannot create custom MCP apps.
</Callout>

<Steps>

<Step>

### Get your connection URL

The connection URL is just the streamable-HTTP endpoint:

```
https://YOUR-DEPLOYMENT/mcp
```

Configure [OAuth 2.1](/docs/mcp/oauth) on your deployment so ChatGPT can
authenticate on connect - you'll pick **OAuth** as the app's auth method
in Step 2. ChatGPT's app can't send a custom `X-API-KEY` header, so the
header-based API-key path that [local clients](/docs/mcp/setup) use doesn't
apply here.

</Step>

<Step>

### Create the MCP app

Open [chatgpt.com/plugins](https://chatgpt.com/plugins), click **Add** (+),
then **Create MCP App**. There is no link that opens the form pre-filled, so
the fields come up empty.

1. Enter a **name** (e.g. `daysurface`); icon and description are optional.
2. Paste your connection **URL** from Step 1.
3. Set **Authentication** to **OAuth** - ChatGPT discovers your server's
   authorization server and walks you through consent. (Use **No Auth** only if
   your deployment runs with no auth configured, e.g. a private internal
   deployment.)
4. Check the box acknowledging the risk warning.
5. Click **Create**.

ChatGPT connects and lists your available tools. Start a new chat so the
tools menu refreshes; enable the app from the composer's **+** menu if it
isn't on already.

OpenAI notes that custom MCP apps give ChatGPT full read/write access to the
tools you expose. Your server still enforces its own auth and policy on every
call as an additional layer.

<Callout type="warn" title="Teams: each member connects with their own account">
With OAuth, every member signs in individually on connect, so tool calls are
attributed to the right user. For a team rollout, have the workspace admin
allow **Create custom MCP connectors** under **Workspace Settings >
Permissions & roles > Connected data**, then let each member add their own app.
</Callout>

</Step>

</Steps>
